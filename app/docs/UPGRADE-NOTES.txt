WHAT'S NEW
----------
1. TWO INTERFACES: VIEW AND EDIT
   - View is a real PDF reader. It has:
       continuous pages; selectable, copyable text
       find-as-you-type that ignores Arabic diacritics, with next/previous match
       fit width, fit page and zoom levels
       a thumbnail sidebar and a two-page layout (in Arabic, page 1 is on the right)
       night reading, read mode (full screen, nothing else on screen) and print
       keyboard: arrows, PgUp/PgDn, +/-, Ctrl+F
   - Edit is the studio you already have.
   - A View | Edit switch sits in the top bar, so you can change at any time.
   - Preferences (the button next to the switch) set which interface a newly opened PDF uses.
     The default is View.
   - Ctrl+K opens a quick search over every tool, in English and Arabic.

2. TOOLS EDIT THE OPEN DOCUMENT (chaining)
   Tool results go back into the open document instead of downloading a new file each time, so you
   can do OCR -> redact -> colors -> optimize and then download once. Undo works after every step.
   A checkbox in the editor (and in Preferences) turns this off. If a result has a different
   number of pages than your selection, it is downloaded instead and the app says why.
   Certificate signatures are always downloaded, because any later change would break them.

3. AUTOSAVE AND RECOVERY (idea from PdfCraft)
   The open document is saved on this device (browser storage) a few seconds after each change.
   If the window closes unexpectedly, the next visit offers "Continue where you left off?".
   This can be turned off in Preferences.

4. BATCH PROCESSING
   New "Batch process" tool. Choose many files or a whole folder, pick one operation (OCR,
   optimize, protect, unlock, repair, redact, Office->PDF ... or a background tint), and get one ZIP
   with the same folder structure plus a _report.txt for any failures.

5. "OPEN WITH" IN WINDOWS
   The installer registers Waraq for PDF files and adds two right-click entries:
     "Open in Waraq" opens the viewer; "Edit with Waraq" opens the editor.
   Double-click uses your default interface. Opening a second file reuses the open window.
   For security, only the main process reads files Windows passes in; the web page never chooses a path.

6. FIX ARABIC TEXT
   - Engine tool (More tools): finds pages whose Arabic text is broken (copies backwards, or as odd
     letter shapes) and rebuilds only those pages with correct searchable Arabic. Other pages are
     copied untouched. It runs on the bundled engines.
   - In the browser, "Extract text" turns odd letter shapes into normal letters automatically (always
     safe). If lines look reversed, it shows a before/after preview and only fixes them if you agree.
     It only treats a line as reversed when a word starts with ة or ى (impossible in correct Arabic),
     so words like فعلا, سهلا or أهلا are never touched.

7. COLORS & BACKGROUNDS (extends the gradient tool)
   Gradient | Solid color | Letterhead | Dark reading
   - Letterhead: put your letterhead image (PNG/JPG) behind every page. Its white areas become
     see-through, so text stays visible. It can fill the whole page or sit at the top or bottom at
     full width.
   - Dark reading: a night copy (black paper, light text). Photos are inverted too.
   All modes keep text searchable and handle rotated pages.

8. CERTIFICATE (DIGITAL) SIGNATURES
   Tool "Certificate signature" (More tools). It signs with:
     - a .pfx/.p12 certificate file plus its password, or
     - a certificate installed in Windows, including USB tokens and national ID cards, which ask
       for their PIN in a Windows window.
   Optional reason, location and a visible signature box on the last page.
   Format: adbe.pkcs7.detached with SHA-256, which Acrobat and other readers validate.
   It works in the Windows desktop app and needs no extra engine. It refuses to re-sign an
   already-signed PDF, since that would break the first signature.

9. ENGINE SETUP EXPLAINED (English or Arabic, matching the interface language)
   The Processing engines dialog explains what applies to the device you are on:
     - Desktop app: nothing to set up, plus what is missing if the Lite edition is installed.
     - Website on a computer: A) install the desktop app (recommended), B) run the companion on
       this PC, or C) a team server with Docker, each step by step.
     - Phone or tablet: what works there and what needs a computer.

10. DOWNLOADS FOR THE RIGHT DEVICE
    Computers and laptops open the Windows app download. iPhone, iPad (which pretends to be a
    Mac, now detected), Android and other phones get the home-screen install. This also works for
    the ?downloads link.

11. UPDATES AND THE SIGNED INSTALLER
    - Help > "Check for updates". On first launch the app asks once whether to check weekly. It
      only reads the public version list on your website; no documents or IDs are sent. It does
      not install by itself: it opens your download page.
      >> ACTION NEEDED: set "pwaraq": {"updateManifest": "https://www.pwaraq.com/downloads/manifest.json"}
         in waraq\package.json. Until then, the menu says updates are not configured.
      The version is read from the installer file names in that manifest (the same rule the
      website uses), so the current live manifest already works. If the list can't be read, the app
      says so; it never reports "up to date" by mistake.
    - Installer names: Waraq-Full-Setup-<version>-x64.exe and Waraq-Lite-Setup-<version>-x64.exe.
      package-desktop-downloads.cjs now publishes from both release\ and release-full\. The website
      accepts these names, shows "— Full" or "— Lite", and allows installers up to 2 GB.
    - Signed installer: buy a code-signing certificate, then before building set
        CSC_LINK=C:\path\your-cert.pfx   and   CSC_KEY_PASSWORD=...
      The build then signs the installer and app with a timestamp. Without them it stays unsigned,
      as before, and Windows shows a warning.

12. FASTER, MORE RELIABLE
    - Heavy tool modules (OCR, templates, advanced, layout, colors, batch) now load only when first
      used, so the first screen loads less JavaScript.
    - The viewer draws only the pages near the screen and frees pages far away, so 200-page files
      stay light.
    - The service-worker cache name changed, so installed copies pick up the new files.
    - The patcher checks every edit point and stops with a clear message, rather than half-patching,
      if a file has changed in an unexpected way.

ROUND 3 (12 October 2026): PAGE EDITOR, LARGE FILES, LIGHT START, ENGINE PAGE

PAGE EDITOR (tool "Edit page", or the crop icon in the viewer for the current page)
  - Existing photos: drag to move, drag the corner to resize, Delete to remove. The photo itself is
    not re-compressed; only where it is drawn changes.
  - Existing text: double-click, type, then press Enter. With the engine (MuPDF) the old text is really
    removed. Without it, the old text is covered with the page's own colour, and the app says that the
    old words can still be found by search or copy.
  - Add text (English as real text; Arabic drawn with correct letter shapes), add images, white-out boxes.
  - Undo inside the editor (Ctrl+Z). Changes are applied to the open document, with normal undo too.

LARGE FILES
  - Up to 2 GB per file in the desktop app (1 GB on the website) and 5,000 pages.
  - Tested: a 2,500-page PDF opened in 1.2 s, the viewer laid it out in 0.65 s, and search found a word
    on page 2,222 in 0.6 s. Thumbnails are only drawn when they scroll into view.
  - Unchanged documents are passed on as the original file instead of being rebuilt.
  - Engine uploads go as raw bytes (not base64). Desktop limits: 2 GB, OCR up to 5,000 pages, 4-hour jobs.
  - Your MV Trenches PDF: 10 A0 pages, but page 1 alone has 14.6 million drawing commands. The browser
